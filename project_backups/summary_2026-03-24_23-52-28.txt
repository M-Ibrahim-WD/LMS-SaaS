Task: Milestone 4 - notifications and background job-ready infrastructure

Prisma models added/modified:
- Added NotificationType enum: WELCOME, INSTRUCTOR_JOINED, PAYMENT_SUBMITTED, PAYMENT_APPROVED, PAYMENT_REJECTED, ENROLLMENT_CREATED, CERTIFICATE_ISSUED.
- Added NotificationJobStatus enum: PENDING, PROCESSED, FAILED.
- Updated User model with notifications relation.
- Added Notification model: id, user_id, tenant_id, type, title, message, is_read, createdAt, read_at.
- Added NotificationJob model: id, notification_id, status, channel, payload, createdAt, processed_at, error.

New functions, APIs, or routes:
- Added backend Notifications module.
- Added NotificationsService with:
  - create(input)
  - myNotifications(user)
  - unreadCount(user)
  - markAsRead(user, notificationId)
  - assertNotificationAccess(user)
- Added routes in NotificationsController:
  - GET /api/notifications/my
  - GET /api/notifications/unread-count
  - PATCH /api/notifications/:id/read
- Added notification creation hooks in:
  - AuthService for welcome notifications
  - StudentInstructorsService for instructor join notifications
  - EnrollmentsService for enrollment notifications
  - PaymentsService for payment submitted, approved, and rejected notifications
  - CertificatesService for certificate issued notifications
- Added backend test coverage in notifications.service.spec.ts for notification creation and job processing.

Background job-ready behavior:
- Notifications now create an outbox-style NotificationJob row alongside each notification.
- Current implementation marks IN_APP jobs as processed immediately.
- This gives a clean handoff point for future BullMQ/Redis workers without changing the notification event shape.

Frontend changes:
- Updated dashboard to fetch and display notifications.
- Added unread count display.
- Added mark-as-read action for unread notifications.
- Extended dashboard types with NotificationItem.

Migrations or schema changes:
- Prisma schema updated with Notification and NotificationJob models and related enums/relations.
- Database synced with prisma db push --accept-data-loss.
- Prisma client regenerated.
