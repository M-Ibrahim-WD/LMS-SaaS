Auth and Runtime Repair Summary

Prisma models added/modified:
- No Prisma schema changes in this repair.

Problems found and fixed:
1. Frontend `Failed to fetch`
- Root cause: backend was down, so `http://localhost:4000/api` was unreachable.
- Backend crash cause: Prisma client runtime/package state was broken. The generated client/package links were inconsistent, which caused startup failures such as:
  - datasource runtime mismatch errors
  - missing `.prisma/client/default` module at runtime
- Fix applied:
  - refreshed workspace install with `pnpm install`
  - regenerated Prisma client with the normal runtime engine using `pnpm --filter @lms/backend exec prisma generate`
  - verified backend was reachable again on `http://localhost:4000/api`

2. Login failures for existing accounts
- Root cause: `LoginDto` incorrectly enforced `MinLength(8)` on login.
- This blocked legacy accounts before bcrypt password verification.
- Fix applied:
  - removed password minimum-length validation from login DTO

3. Fragile email/input handling
- Fix applied:
  - normalized auth emails with `trim().toLowerCase()` in backend auth/users flow
  - normalized login/register email on frontend before submit
  - normalized student invite code to uppercase in backend and frontend
  - trimmed organization name and full name before submit/use

4. Poor error visibility in auth UI
- Fix applied:
  - login and register pages now surface actual backend error messages instead of always showing a generic failure string
